# 安全自评报告

本报告说明行止（ActSure，内部仓库/包名 AgentBank）的权限实现、安全测试和已知风险。评估对象是本地模拟银行、商户和设备，测试使用合成身份与交易。系统不连接真实银行，也不处理真实资金。

## 评委验证入口

按 [本地运行说明](LOCAL-RELEASE.md) 启动服务，再打开 [银行 App](http://127.0.0.1:8001/app/) 体验查询、确认和设备强验证。完整操作路径见 [评委体验指南](LOCAL-REVIEW-GUIDE.md)。

固定安全评测入口为 [评测面板](http://127.0.0.1:8001/app/eval.html)。从启动器生成的 `.tmp/local-demo/eval.env` 读取 `AGENTBANK_ADMIN_TOKEN`，填入页面令牌框。面板展示逐条用例结果、审计证据和未授权记账检查。上述地址仅在本机服务运行后可用。

## 权限分级实现

| 等级 | 执行方式 | 代表场景 | 关键校验 |
|---|---|---|---|
| 绿色 | 自动执行 | 本人余额、交易查询 | 有效会话、资源归属和只读范围 |
| 黄色 | 展示详情并取得用户确认 | 满足其他策略条件且日累计不超过 1000 元的小额转账 | 对象、金额、操作哈希、展示哈希和凭证有效期 |
| 红色 | 用户确认后通过模拟设备验证码验证 | 日累计超过 1000 元的转账、新收款人转账、理财申购、挂失和 PIN 变更等 | 独立设备边界、一次性验证码及提交时的动态复核 |
| 拒绝或转人工 | 不执行付款 | 身份不符、越权、参数篡改或高欺诈风险 | 服务端策略和业务状态；模型不能降低权限 |

权限等级与欺诈风险分别判断。高欺诈风险（`high`）拒绝付款并转人工；中等或未知风险（`medium` / `unknown`）进入真实时间冷静期并占用可用资金，到期后须重新确认和强验证。业务时钟快进不能缩短冷静期。

确认和强验证均核对用户归属、任务版本、凭证用途与有效期、对象与金额、操作和展示哈希。提交前重新读取账户、额度和风险状态，授权消费与账本变动在同一事务内完成。修改任务会使旧授权失效；结果未知时沿原操作核实，不重新派发可能已提交的付款；计划支持暂停、恢复和取消，取消仅撤销未执行授权。

## 安全机制与验证证据

| 验证目标 | 实现行为 | 代表性测试 |
|---|---|---|
| 授权不可绕过 | 拒绝跨用户、改参、过期凭证和提交前风险变化 | [授权完整性](../backend/tests/test_authorization_integrity.py)、[提交复核](../backend/tests/test_m3_commit_guards.py) |
| 失败与重试不重复付款 | 沿用原操作标识核实结果；未知结果不重派资金指令 | [消息崩溃恢复](../backend/tests/test_message_crash_recovery.py)、[恢复接口](../backend/tests/test_m3_recovery_api.py) |
| 计划可中断和恢复 | 暂停阻止未来派发，取消撤销未执行授权并释放剩余预留 | [计划生命周期](../backend/tests/test_review_plan_lifecycle.py)、[DAG 恢复](../backend/tests/test_m2_dag_recovery.py) |
| 防止提示注入和虚构结果 | 白名单工具与参数来源校验；回复引用服务端事实；不执行任意生成代码 | [计划安全](../backend/tests/test_free_dag_security.py)、[安全回归](../backend/tests/test_m3_security_closure.py) |
| 账务结果一致 | AA 双方借贷、订阅扣款、资金预留、理财持仓和流水可对账 | [财务完整性](../backend/tests/test_financial_integrity_closure.py) |
| 设备验证失败可控 | 验证码错误计数按用户持久化；锁定策略由服务端执行 | [安全回归](../backend/tests/test_m3_security.py)、[安全闭环](../backend/tests/test_m3_security_closure.py) |

审计事件经过敏感信息处理后写入哈希链。数据库外的 HMAC 检查点用于检测数据库与库内检查点同时遭截断。坐席只能提交建议和重试申请，不能代用户授权付款。

## 测试范围与结果含义

固定本地评测共有 227 条：99 条能力旅程、80 条安全用例、27 条误拦用例、10 条额外欺诈用例和 11 条恢复用例。能力映射见 [能力追溯表](capability-traceability.md)。

80 条安全用例分为八类，每类 10 条。每条用例核查其实际数据库中的操作、凭证消费和借贷分录；一次完整本地运行的未授权记账数为 0。复现时应同时核对逐条结果、审计校验和未授权记账检查。该结果只适用于这些合成样例，不是对所有攻击或生产环境的保证。

固定测试不能推导真实用户任务完成率、线上欺诈召回率、误拦率或生产性能。检查命令和结果文件见 [本地运行说明](LOCAL-RELEASE.md)。

## 已知风险与边界

| 风险或限制 | 影响与控制措施 |
|---|---|
| 演示身份与模拟设备 | 账号选择器不是生产登录。模拟 OTP 不是短信、人脸或 U 盾；PIN 仅在本地以带随机盐的 PBKDF2 哈希保存。生产使用需接入真实身份与认证系统。 |
| 第三方模型的数据处理 | 模型服务商及配置的中继会接收任务所需的提示词、用户话语和受控事实。应用脱敏不保证第三方零留存；使用合成数据，并按服务条款核查保留与训练用途。 |
| 模型可用性与反诈特征 | 配置的备用模型路径未作真实生产切换验收；在线反诈未完整接入关系图和行为特征。模型失败或风险未知不能作为安全许可。 |
| 审计密钥与检查点窗口 | 持有 HMAC 密钥者可以生成检查点；最近检查点之后的审计尾段存在截断窗口。应独立保管密钥和检查点。 |
| 本地存储与进程状态 | 用户安全计数和模型预算存入 SQLite；工具基础设施熔断为进程内状态，重启会重置。多 worker 需共享数据库和锁目录，不宣称支持分布式数据库部署。 |
| 外部部署与机构接入 | Docker 双实例运行、公网 HTTPS、真实飞书租户及真实银行、商户、短信等接口需要独立验收。本地测试和 CI 构建不构成生产部署验收。 |

数据流和控制细节见 [安全设计](security-design.md)。
