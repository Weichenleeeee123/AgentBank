# 第 5 轮前：Claude 自审 PLAN v2（结构、完整性、严谨性、创新性）

审查标准：拿到这份文档的队员不需要再问任何问题，就能开工；评委关心的每一项都能在文档里找到对应的设计、测试和提交物。

## 一、结构缺口（v2 缺了整个章节）

| # | 缺口 | 为什么必须有 | v3 补在哪里 |
|---|---|---|---|
| S1 | 文档说明：版本、状态、读者、阅读路径、约定、变更控制 | 多人并行开发，必须知道哪里是权威、怎么改 | §0 |
| S2 | 用户、痛点与核心旅程 | 评分里有"真实问题解决度"；没有用户画像，创新点就没有依据 | §2 |
| S3 | 创新点与交互设计单独成章 | 创新和交互体验占 30%，v2 里这部分内容零散地分布在各节；评分细则里的 7 个子项（场景新颖性、真实问题解决度、对话轮次效率、追问、错误恢复、口语化输入、超范围兜底）都没有逐项对应的设计 | §4 |
| S4 | 单轮处理的完整时序：每一轮调用几次 LLM、按什么顺序调、每次带什么上下文 | 循环补上以后，还缺"一轮对话从头到尾怎么走" | §6.1 |
| S5 | LLM 的角色分工、上下文怎么构造、提示词怎么管理 | 规划器到底能看到什么，是安全论证的前提 | §6.2、§6.3 |
| S6 | 核心算法 | 它是必交的"核心算法说明"，可 v2 只在提交物表里列了名字，没有给出定义 | §10 |
| S7 | 对外接口清单 | Codex 初稿里有，合并时丢了；评委可以绕过 UI 直接测接口 | §7.10 |
| S8 | 代码仓库结构、CI、配置和密钥管理、可观测性 | 开工的第一天就要用到 | §13 |
| S9 | 性能和成本预算 | Codex 初稿里写的 P95 ≤ 8 秒在合并时丢了；评审周期 6 天，额度能不能撑住没算过 | §13.6 |
| S10 | 部署、评审期运维（11-03 到 11-08）、决赛准备（11-28/29 线下黑客松） | v2 只计划到 11-02；可决赛是现场黑客松，架构要能现场扩展 | §17 |
| S11 | 需求追溯矩阵：brief 每条要求对应到设计、测试 ID 和提交物 | 证明全覆盖的唯一办法 | 附录 A |
| S12 | 假设清单（假设不成立时会有什么影响），以及术语表 | 假设散落在各处；G/Y/R、mandate、Prepare 这些术语没有统一定义 | 附录 E、F |

## 二、内容矛盾和不严谨的地方

| # | 问题 | 改法 |
|---|---|---|
| C1 | §6 写"OTP 最多试 5 次"，U16 写"连续失败 3 次就锁定" | 统一为单个 OTP 最多试 3 次，和 U16 一致 |
| C2 | 日累计的"一天"按哪个时钟划分没写；业务时钟能快进，而安全相关时间用的是真实时间 | 日累计按**业务日**计（定时转账也按业务日执行）。只有评测实例能拨业务时钟，公共实例不能，这一点要明确写出来 |
| C3 | 理财申购算不算支出累计没写 | 不算对外支出（资金变成了自己的资产），但申购本身始终是 R |
| C4 | 计划 JSON 里 `trigger: "schedule.due"` 没有给出触发时间 | 改为 `trigger: {"type": "schedule", "at": "2026-11-13T09:00:00+08:00"}` |
| C5 | P08 那一行的决策列是"—"，格式不对 | 拆成两行 |
| C6 | 契约冻结之后怎么改没写（Claude 初稿里有，合并时丢了） | 写进 §0 和 §15 |
| C7 | 坐席是什么身份、怎么登录没写 | 单独的 staff 角色和登录；坐席的操作同样写审计 |
| C8 | 管理接口（拨业务时钟、重置数据）怎么保护没写 | 只在评测实例开放，需要 admin 令牌 |
| C9 | 公共演示地址被滥用（刷 LLM 费用）没考虑 | 演示账号只发给评委；按账号和 IP 限流；设预算熔断 |
| C10 | 指标里缺"平均轮次"和"延迟"，而评分细则写了"对话轮次效率" | 补上 |
| C11 | 反诈检测器内部怎么判没写：用哪些信号、怎么算分、阈值多少 | 写进 §10 |
| C12 | 超出范围的问题只有一句"兜底" | 分类给出回复策略（§4.4） |
| C13 | 被拦截时用户看到什么没规定 | 制定"可解释拒绝"规范：规则 ID、通俗原因、安全的下一步 |
| C14 | 攻击集要靠 LLM 批量生成，但生成流程和人工复核没写 | 写进 §14 |

## 三、创新性还可以加强的地方（只加低成本、能拿分的）

| # | 点子 | 成本 | 处理 |
|---|---|---|---|
| I1 | **评委自测面板**：在线上实例里一键跑攻击集，实时显示结果和审计链接。评委 1 分钟就能验证我们的安全声明 | 低，复用评测运行器 | 承诺做，排在 M3 |
| I2 | **可解释拒绝**：每次拦截都说明是哪条规则、为什么、接下来可以怎么做 | 低 | 承诺做 |
| I3 | **计划可视化**：DAG 实时进度图，每个节点显示状态和授权 | 低到中，复用任务卡组件 | 承诺做 |
| I4 | **亲情守护**：用户可以设一位家人，反诈判 high 时同步通知这位家人（通知走模拟渠道） | 低到中 | 可选，M3 有余量才做 |
| I5 | 主动发现需求（X01）、保护性操作快速通道、"安全不牺牲体验"的数字 | v2 已经有 | 在 §4 里统一讲清楚 |
