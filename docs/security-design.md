# 安全设计与数据流

## 信任边界

用户通过 App/PWA 或签名 IM 进入银行会话。模型只产生结构化建议，不能直接写账本、签发授权或声明事实成功。服务器验证工具白名单、参数来源、用户归属、当前业务状态与策略后生成确认卡；红色操作经独立模拟设备 OTP。确认与验证都在提交前重新检查权限。实现细节见 [架构](architecture.md)、[算法](algorithms.md) 和 [安全自评](security-self-eval.md)。

## 授权与资金

整数分金额及收款账户快照进入操作哈希，确认卡进入展示哈希。凭证绑定 owner/revision/有效期/用途，不可跨任务复用。修改任务作废旧授权；风险或额度方向变化不能用旧低等级授权执行。AA 参与者本人支付，使用真实模拟收款账户、共享日累计、动态风险和 MFA 规则；幂等键防重复借贷。

生日未来授权限定对象、金额、次数及日期；父计划暂停阻断调度，取消撤销未执行 mandate/job 并释放剩余预留。已执行款项需查询或明确补偿，不能称为全部撤回。

## 注入、隔离与审计

不执行模型生成的任意 Python/SQL/shell。分析使用白名单 DSL，读取服务端强制加本人过滤；外部资料不授予权限。会话锁、消息幂等、事务和 Operation 唯一键分别约束并发与重试。关键事件经 DLP 后写哈希链，独立 HMAC 检查点检测截断；密钥/检查点需要独立保存。OTP 失败与安全拦截计数持久化，工具基础设施熔断为进程内状态。

## 模型与数据披露

可配置的 OpenAI-compatible provider（以及配置的 relay）会收到完成任务所需的提示词、用户话语和受控工具事实。本项目只使用合成演示身份、账户与交易，仍应避免在聊天中输入真实敏感数据。应用侧 DLP 与最小化不能证明第三方不留存；远端保存地域、保留期和训练用途依具体服务合同确认，当前没有零留存保证。备用 provider 未配置时不声称具有真实双供应商可用性。

数据库、会话/设备令牌与本地审计密钥留在操作者环境，源码包排除这些内容。PWA 只缓存静态资源；账户 API 不缓存。演示账号选择器不是生产登录，模拟 OTP 不是银行认证。本地 HTTP 默认仅 loopback；生产 HTTPS、真实登录、KMS、机构及真实飞书租户需要独立验收。
