# 核心算法与当前验证

## 自然语言解析

离线 `IntentParser` 识别余额、流水、账单、理财、卡片、订阅、生日和转账意图。金额统一转为分；金额、收款人、产品等关键槽位缺失时返回一次澄清。多轮会话由 `AgentOrchestrator` 保存未完成槽位并合并下一条消息。

已配置的 OpenAI-compatible provider 使用四个结构化角色：planner 提出能力、槽位及 DAG；explorer 在最多五步内调用白名单只读工具；reply 仅复制服务端事实片段，正文不换算数字；fraud 返回有限分类与置信度。输出必须通过 schema、工具白名单和参数来源校验，金额、对象与日期不能由模型凭空添加。补充转账金额时优先合并用户先前的收款身份与本轮确定性金额，模型切换姓名/电话/别名路由不能替换收款人。用户明确指定新收款人时才更新身份。

模型失败会重试主 provider 并尝试已配置的备用 provider；没有可用结果则确定性降级。风险分类未知不能作为安全许可。模型调用预算独立持久化，即使后续业务失败也不回滚已消耗调用。真实 provider 冒烟与固定评测分开留存，不把 fake transport 当成网络联调。

## 计划校验

`PlanValidator` 使用 Kahn 拓扑排序检测环，拒绝未注册工具、缺少幂等键、命令节点缺补偿、写参数含 `untrusted_field` 的计划；`$ref` 只能指向前置依赖节点。

## 账单分析

DSL 只允许 `transactions` 数据源、白名单字段、字段运算符、分组和 `sum/count` 指标；服务端强制按 `user_id` 过滤，并写入 DSL 哈希审计。异常检测包括重复扣款、MAD 稳健离群、境外小额试探后大额和首次商户大额。

## 权限与恢复

高风险转账在账本提交前拒绝；中风险建立真实时间冷静期。熔断按用户持久化安全拦截计数。Saga 在部分失败后逆序调用补偿；unknown 结果恢复为 processing，沿用原幂等键。

转账操作哈希覆盖付款账户、收款人及收款账户快照、整数分金额和备注；展示哈希覆盖完整确认卡。提交时重新核对 owner、revision、receipt 状态与有效期、操作/展示哈希及当前账户状态，再在原子事务中消费授权并记借贷分录。同一消息 ID 只能绑定一个 payload；新消息重新读取当前事实；处理中的同会话新消息明确拒绝，避免多轮状态交错。

## 当前证据

本地评测运行器当前执行 33 项能力各 3 条，以及 M3 安全恢复样例。实际命令和结果见 `docs/M2-M3-STATUS.md`；这些结果来自模拟数据，不能替代真实部署或真实银行效果。

## 可复核算法细节（2026-11-01）

| 算法 | 输入 → 输出 | 关键步骤 / 拒绝条件 | 示例 |
|---|---|---|---|
| 任务关系 | 当前用户话语、历史与待确认任务 → new/revise/cancel/keep/auto | planner 的 task_reference 必须是当前话语中的原文；模型输出通过 schema 后，修订原子作废旧记录；显式新任务保留原任务；离线仅支持有限命令语法 | 20 元改成 30 元：旧凭证失效；“再转一笔，原来的保留”：两个独立任务 |
| 动态权限 | 当前账户/卡状态、风险、金额、日累计 → confirm/MFA/拒绝 | 准备时绑定快照；提交事务再次读取最新状态；若权限升级，旧普通确认失败，须重新准备强验证 | 先降到 500 后，旧 900 元凭证已构成提额，不能普通确认 |
| AA 结算 | bill_id、参与者身份 → 真实账户借贷、份额状态 | 服务器解析本人份额及发起人账户；哈希绑定；复核风险/日累计/MFA；原子借贷、消费凭证、更新份额；每份额唯一 Operation | 参与者付 2000 元：本人 -2000，发起人 +2000；重试不重复入账 |
| DAG 生命周期 | 已校验 DAG、节点实际状态 → 父计划状态 | 拓扑排序 O(V+E)；scheduled 只代表安排；有未来任务则 waiting_trigger；到期检查父计划/mandate；失败为 partial；取消撤销未执行授权和剩余预留 | 暂停后快进不下单，恢复后每单只执行一次 |
| 风险问卷 | 版本、10 个整数答案 0..5 → 分数、C1..C5、有效期 | 拒绝布尔/缺题/越界/旧版本；sum 得 0..50，按 ≤10/20/30/40 分为 C1/2/3/4，否则 C5；保存版本和答案；次年同日有效，闰日取月末 | 10 个 3 分为 30、C3；2028-02-29 测评到 2029-02-28 |
| 订阅识别 | 本人商户流水 → 周期订阅候选 | 少于两笔跳过；至少一个周/月/年间隔匹配才进入候选；保留证据而非推断已签约 | 单次商城消费不再标为疑似订阅 |
| 分析与异常 | 限定本人 DSL / 流水 → 聚合和可追溯交易 ID | 字段/运算白名单、禁止任意代码；重复扣款、MAD 离群、试探后大额、新商户规则；缺数据显式披露 | 月报按收入/支出分列，不把转账伪装成消费 |

资金伪代码：校验 owner → 读取当前快照 → 核对操作/展示哈希及授权 → 重算策略 → 原子消费授权、更新余额与借贷分录 → 写审计。任一步失败回滚，不根据模型生成的“成功”文字记账。

消息幂等以 user/conversation/message_id 和 payload 绑定；重复返回持久结果，改参数拒绝。unknown 不盲目重派资金指令。模型调用不持有账本大事务。固定样例结果只代表该样例集；线上任务完成率、四类实际误拦率和端到端 P95 仍需单独采样。
