# 本地评审与演示顺序

本作品使用模拟银行、商户、手机和 IM。演示账户是种子测试账户，不输入真实银行卡、密码或验证码。启动和独立凭证见 [LOCAL-RELEASE.md](LOCAL-RELEASE.md)。

## 入口

启动评测实例后打开 `http://127.0.0.1:8001/app/`，设备页 `/app/device.html`，模拟 IM `/app/webim.html`，计划页 `/app/plan.html`，坐席页 `/app/staff.html`。管理员和坐席凭证只在本机使用，不放进截图、PPT 或源码包。

## 约 8 分钟答辩演示

1. **余额和小额转账（90 秒）**：登录 `user_001`，问“查余额”，再问“给房东转账”，补充“20元”。核对确认卡后确认，再次问余额。以服务端事实和借贷结果为准，不把待确认当成成功。种子余额 5000 元，首次成功转 20 元后应为 4980 元。
2. **强验证（90 秒）**：用 `New-DevicePairing.ps1` 为该用户签发一次性配对码，独立设备页完成配对并读取收件箱，保持连接。在 App 专用安全表单选择本人卡片、准备模拟 PIN 变更，确认后在设备页读取本次 OTP，再回 App 专用表单提交。聊天不接收 PIN/OTP，演示不修改真实卡片。
3. **模拟 IM（60 秒）**：登录独立 IM 身份，显式绑定银行会话。在私聊完成多轮小额转账和确认；红色业务只给 App 验证链接；切换群聊，确认不展示余额、确认凭证等私密内容。
4. **生日联动（90 秒）**：通过 Agent（已配置主模型）或 birthday API 准备 `event_birthday` 计划。在 App 计划链接核对预算、订单和时间，完成确认/验证。打开计划图，观察依赖节点、授权和结果；用评测环境业务时钟快进观察到期调度。暂停/恢复/取消分别展示状态，取消和部分失败的释放/补偿以账本与节点结果核对。评测时钟不会缩短真实时间冷静期。
5. **异常和人工恢复（60 秒）**：演示诱导转账被拒绝、错误验证码计数和锁定。坐席仅写建议草稿与重试申请，再由用户检查通知并重新授权。坐席不能代用户批准付款。
6. **证据（60 秒）**：展示当前发布目录的 `gates.json`、完整评测 JSON 和 HTTP 自测结果，明确固定样例覆盖与真实业务效果的差别。公开演示时隐藏本机凭证。

## 状态核对

`awaiting_confirmation` / `awaiting_mfa` 均未完成；`scheduled` 是已安排、等待执行；`cooling_off` 需等待真实时间并二次验证；`unknown` 先查账和联系人工，不能另发一笔付款；只有权威终态才能声明成功。

无 provider 时可复现确定性查询、表单与安全门禁，不能把确定性降级当作真实模型联调。主模型、Docker、公网和真实飞书各自看独立证据。

## 可选视频

赛题视频为可选，限制 5 分钟。可按前四步各压缩至 45–60 秒，再用 30 秒展示审计与边界。当前不把脚本、截图或 PPT 当成已录制视频。
